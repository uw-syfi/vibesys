# Minimize shared-prefix HTTP time to first token on Apple Silicon

Serve the pinned `mlx-community/Llama-3.2-3B-Instruct-4bit` model through an
OpenAI-compatible streaming `/v1/chat/completions` endpoint. Target: Apple M5
MacBook Air with 16 GB unified memory. Minimize `p50_ttft_ms`; secondary metrics
are end-to-end latency, actual output token throughput, and server peak RSS.

The authoritative workload is `workload.json`: approximately 4096 shared-prefix
tokens, four concurrent questions, temperature zero, at most 64 generated tokens
per question, and one warmup on the same shared document. Preserve these values,
the model revision, 4-bit weights, and the model's chat template. Expected answers
must be generated by the model from evaluator-supplied randomized facts in the
document. Each question has its own correct answer. Streams must arrive and parse
incrementally as OpenAI-style SSE, complete normally, and terminate with `[DONE]`.

The candidate entry point is root `server.py`, accepting `--model-path`, `--host`,
and `--port`. Requests use the `default_model` alias, mapped to the pinned
local model, so the stock server reuses the already loaded snapshot. It must load the provided local model and serve on the requested
address. Evaluation owns startup, readiness, warmup, requests, and shutdown.
Keep serving in the launched process so external process peak RSS remains
comparable. Do not delegate inference to another service or a child process.

Stock MLX-LM batching and caching form the initial baseline. Caching, scheduling,
batching, prefill sizing, or other valid alternatives may be explored; prefix
caching is not a required implementation. Never answer from a hard-coded map,
parse sentinel facts to bypass model inference, change token/precision budgets,
prepopulate answers, or alter the held-out evaluator or its inputs.

All task-owned files are read-only during optimization. Use only the cached
model. No model downloads, CUDA/NVIDIA execution, or reference 8B model loads.
Exact HTTP prompt-processing duration and Metal peak allocator memory are
unavailable from the stock server. Optional telemetry may report explicitly
measured values later; never substitute TTFT for prompt-processing duration or
RSS for total unified/Metal memory.

Every measurement must retain its commands, workload identity, correctness
outcome, raw request timings/token counts, candidate identity, and memory scope.
Any failed warmup, incorrect answer, malformed/incomplete stream, timeout, or
invalid required metric invalidates the evaluation. Establish a passing stock
baseline before evaluating optimizations.
